Contribuir uma recipe

Cada banco/fintech suportada pelo Extratus é um arquivo em src/recipes/<dominio>.ts. Se o seu banco não está coberto, você pode usar um agente com browser tools (Claude in Chrome, Computer Use, ou outro) para descobrir os endpoints e o schema — depois abre um PR.

1. Pré-requisitos

  • Estar logado na sua conta do banco em uma aba do Chrome.
  • Um agente com acesso ao navegador. Recomendado: Claude in Chrome ou Claude Code com o MCP claude-in-chrome.
  • O repositório do Extratus clonado localmente (você vai abrir o PR a partir dele).

2. Cole este prompt no seu agente

O agente vai navegar pela sua sessão logada e produzir um relatório que vira a recipe.

Você vai descobrir como o site do meu banco renderiza o extrato, e produzir uma recipe TypeScript para o projeto Extratus (https://github.com/<owner>/extratus). Eu já estou logado na conta. NÃO clique em botões que mudem estado (transferir, pagar, confirmar) — você é READ-ONLY.

OBJETIVO
Mapear como obter, de forma programática, a lista completa de transações do extrato — incluindo paginação e filtros de data — e devolver um arquivo TypeScript no formato Recipe do Extratus.

PASSO A PASSO

1. Abra a página principal de extrato do banco e me diga a URL. Tire screenshot.

2. Antes de qualquer clique, inspecione o HTML inicial procurando dados embarcados (SSR):
   - `<script id="__NEXT_DATA__">` (Next.js)
   - `<script id="__NORDIC_RENDERING_CTX__">` (Mercado Libre)
   - `window.__INITIAL_STATE__`, `window.__PRELOADED_STATE__`, `window.__APP_DATA__`
   - Qualquer `<script>` cujo textContent contenha uma transação visível (procure por um valor R$ ou nome que aparece na tela).
   Reporte: qual padrão SSR (se houver) e o JSONPath até o array de transações.

3. Capture as requisições de rede (XHR/fetch) que populam a lista. Aplique um filtro de data (ex: "últimos 30 dias") e role a página. Reporte:
   - URL exata de cada endpoint que retorna transações (preserve query params).
   - Method, headers críticos (CSRF, X-Requested-With), cookies necessários.
   - Se requer body POST: mostre o payload.

4. Pegue UMA transação de exemplo e me mostre o JSON cru completo do item, com TODOS os campos. Identifique:
   - `id` ESTÁVEL (para FITID, dedup em reimportação) — geralmente prefixado ou um UUID; NUNCA use um índice de array.
   - data: idealmente ISO 8601 UTC; se for "DD/MM/YYYY" diga.
   - valor: formato exato (centavos separados? sinal incluso? separador de milhares?).
   - sinal de crédito/débito: existe campo canônico (ex: `type:"in"|"out"`)? Ou é inferido pelo sinal do valor?
   - moeda: campo explícito ou implícito BRL?
   - descrição: combina título + descrição? Tem categoria do usuário?

5. Paginação. Iterate até a última página. Como funciona?
   - `?page=N` 1-indexed ou 0-indexed?
   - cursor (`?since=...`, `?after=...`)?
   - scroll infinito (verifique XHR a cada scroll)?
   Reporte o número total de transações reportado pelo backend e confirme que iterando você vê o mesmo total.

6. Lançamentos especiais. Verifique se aparecem com tag distinta:
   - Rendimento automático (cofrinho, savings)
   - Pix (entrada/saída)
   - Cartão (compra parcelada)
   - Cashback / estorno
   Marque a regra (ex: "metadata.kind=investment ⇒ Rendimento").

7. Multi-conta. O site tem mais que uma conta exportável (corrente + cofrinhos + cartão)? Liste cada uma com a URL e o endpoint correspondente.

ENTREGÁVEIS

A. Um relatório curto em markdown com cada um dos 7 itens acima preenchido.

B. Um arquivo TypeScript pronto para `src/recipes/<dominio>.ts` seguindo este padrão:

```ts
import type { Recipe } from './_schema'
import type { RecipeOutput } from '@/types/transaction'
import { fetchNordicCtx } from '@/engine/nordic-ssr'  // só se for site SSR Nordic
import { sleep } from '@/engine/recipe-helpers'
import Decimal from 'decimal.js'

export const bancoX: Recipe = {
  site: 'bancox.com.br',
  version: 1,
  label: 'Banco X',
  match: (url) => /(^|\.)bancox\.com\.br$/.test(url.hostname),
  extract: async ({ window }) => {
    // 1. fetch páginas (loop sobre `page` até o total reportado)
    // 2. dedup por id se houver overlap
    // 3. map cada item para NormalizedTransaction: { fitId, postedAt: Date, amount: Decimal, currency, description, type }
    // 4. retornar 1+ RecipeOutput (um por conta)
    return []
  },
}
```

REGRAS NÃO NEGOCIÁVEIS
- `amount` é Decimal (decimal.js). NUNCA parseFloat.
- `postedAt` é `Date` em UTC. Se a fonte for "DD/MM/YYYY", parseia explicitamente em horário de Brasília e converte.
- `fitId` é estável: duas exportações do mesmo período devem produzir os MESMOS fitIds.
- `extract` é IDEMPOTENTE: rodar 2x não duplica.
- Entre requests, dê `await sleep(250)` para não disparar antibot.

Comece pelo passo 1 e vá em sequência. Mostre seu trabalho a cada passo.

3. Depois que o agente terminar

  1. Salve o arquivo TS em src/recipes/<dominio>.ts.
  2. Registre em src/recipes/_registry.ts.
  3. Adicione o domínio em host_permissions e em um bloco content_scripts.matches no src/manifest.json.
  4. Rode npm test e npm run build.
  5. Teste exportando um OFX e importando no Afino (ou no software que você usa).
  6. Abra um PR com o relatório markdown na descrição. A comunidade vai ter contexto pra revisar.

Por que a comunidade?

Open Finance não cobre tudo (carteiras de cripto, contas legacy, fintechs menores, cofrinhos com rendimento). A ideia do Extratus é cada um contribuir o seu — uma vez que a recipe está no repo, todo mundo se beneficia. Sem senha viajando pra lugar nenhum: tudo roda no seu navegador, lendo o que você mesmo já está vendo.
