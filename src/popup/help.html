Gerar uma recipe com IA

Cada banco/fintech suportado pelo Afino Extratus é uma recipe JSON declarativa. Se o seu banco ainda não está coberto, use um agente com browser tools (Claude in Chrome, Computer Use) pra investigar a sessão logada e produzir o JSON. Depois, cole no popup ou abra um PR.

1. Pré-requisitos

  • Estar logado na sua conta do banco numa aba do Chrome.
  • Um agente com acesso ao navegador. Recomendado: Claude in Chrome ou Claude Code com o MCP claude-in-chrome.

2. Cole este prompt no seu agente

O agente vai navegar pela sua sessão logada e produzir um arquivo JSON no schema afino-extratus-recipe/v1 que você pode colar direto no popup do Afino Extratus. 

Você vai descobrir como o site do meu banco renderiza o extrato e produzir uma recipe JSON declarativa para o Afino Extratus. Eu já estou logado na conta. NÃO clique em botões que mudem estado (transferir, pagar, confirmar) — você é READ-ONLY.

OBJETIVO
Mapear de forma programática a lista completa de transações do extrato (incluindo paginação e filtros de data) e devolver um único arquivo JSON no schema "afino-extratus-recipe/v1".

PASSO A PASSO

1. Abra a página principal de extrato e me diga a URL. Tire screenshot.

2. Antes de qualquer clique, inspecione o HTML inicial procurando dados embarcados (SSR):
   - <script id="__NEXT_DATA__"> (Next.js) — use source.type="ssr-next"
   - <script id="__NORDIC_RENDERING_CTX__"> (Mercado Libre) — use source.type="ssr-nordic"
   - Para outros patterns SPA + XHR JSON, use source.type="rest-json"
   Reporte: padrão SSR detectado e o JSONPath até o array de transações.

3. Capture as requisições de rede (XHR/fetch) que populam a lista. Aplique um filtro de data e role a página. Reporte:
   - URL exata, method, headers críticos.
   - Body POST quando houver.

4. Pegue UMA transação de exemplo e mostre o JSON cru completo do item. Identifique:
   - id estável (FITID): geralmente UUID ou prefixado; NUNCA use índice.
   - data: ISO 8601, "DD/MM/YYYY" (use "br-date") ou unix.
   - valor: número direto (use { path, scale }), "1.234,56" (use { path, format:"br" }), ou bitácora (use { fractionPath, centsPath }).
   - sinal: campo canônico (use creditWhen / debitWhen com path+equals/notEquals) ou inferido pelo sinal do amount (creditWhenSign).
   - moeda: campo explícito ou default da conta.
   - descrição: combinação de title + description? Use { template: "{title}[ — {description}]" }; o grupo [ ] some quando vazio.

5. Paginação. Iterate até a última página:
   - "page-count" se tem total de páginas no response: pagination.type="page-count", totalPath=<path>
   - "cursor" se tem next-cursor: pagination.type="cursor", nextPath=<path>
   - "none" se single page

6. Multi-conta. Se há corrente + cofrinhos + cartão:
   - Conta única: account.kind="single"
   - Sub-contas dinâmicas: account.kind="discovered" com discover.source/list/fields e nameTemplate.

ENTREGÁVEL
UM arquivo JSON, válido contra o schema abaixo. Nada de TS/JS — apenas JSON declarativo. Exemplo mínimo:

```json
{
  "$schema": "afino-extratus-recipe/v1",
  "site": "bancox.com.br",
  "version": 1,
  "label": "Banco X",
  "matchHosts": ["www.bancox.com.br", "*.bancox.com.br"],
  "accounts": [
    {
      "kind": "single",
      "id": "checking",
      "name": "Banco X — Conta",
      "type": "checking",
      "currency": "BRL",
      "extract": {
        "source": {
          "type": "rest-json",
          "url": "https://api.bancox.com.br/extrato?page={page}[&period={period}]"
        },
        "pagination": { "type": "page-count", "totalPath": "totalPages", "max": 50 },
        "periodMap": { "month": "30d", "last_week": "7d" },
        "list": "data.movements",
        "fields": {
          "id": { "path": "id" },
          "postedAt": { "path": "date", "format": "iso" },
          "amount": { "path": "amount", "scale": 0.01 },
          "description": { "template": "{title}[ — {description}]" },
          "type": { "creditWhen": { "path": "type", "equals": "credit" } }
        }
      }
    }
  ]
}
```

REGRAS NÃO NEGOCIÁVEIS
- O JSON precisa validar contra "$schema": "afino-extratus-recipe/v1".
- matchHosts deve cobrir os hosts reais que o engine vai chamar (segurança: o engine recusa fetches fora desses hosts).
- "id" precisa ser estável: duas exportações do mesmo período → mesmos ids.
- Datas em UTC ou ISO 8601 quando possível.

Comece pelo passo 1 e vá em sequência. Mostre seu trabalho a cada passo.

3. Depois que o agente terminar

  1. Copie o JSON gerado.
  2. No popup do Afino Extratus, abra Importar recipe customizada (JSON), cole e clique Importar. O JSON é validado contra o schema antes de ser salvo.
  3. Volte ao site do banco logado e clique Exportar OFX. Confira o arquivo gerado.
  4. Quando a recipe estiver estável, abra um PR no repositório com o JSON em src/recipes/<dominio>.json. Outros usuários do Afino Extratus passam a ter suporte built-in.

Por que JSON declarativo?

Recipes coladas pelo usuário rodam num engine que só interpreta primitivos conhecidos (sources, paginação, mapeamento de campos). Não há eval de JS arbitrário. Além disso, o engine restringe os fetches aos hosts declarados em matchHosts — uma recipe não consegue chamar nenhum servidor externo sem você ver o domínio antes de importar.
